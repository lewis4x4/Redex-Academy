# M3 — Branching Egress-Fail Scenario (AC-103, AC-203)

- **Effort tier:** standard
- **Phase:** MVP

## Objective
Author and ship the branching scenarios on the F5 branching engine: AC-103's "Trapped or Free?" awareness walk and AC-203's **mandatory** egress-fail flagship sim — wrong egress choices show the trapped-occupant consequence with the post-mortem replay; scored via the shared Verdict service with the safety veto live.

## Depends on
- **F5** (branching engine + JSON Schema + Zod + Verdict/safety-veto hook + xAPI emitter + 2D fallback + colorblind-safe rendering), **S1** (AC-103/AC-203 units + competencies + the AC-203 safety line-items), **M1** (enrollment/gating so the scenario is reachable).

## Consumes (contracts)
- F5's branching JSON Schema + Zod (`packages/sim-schemas`) and engine API + Verdict service (`packages/sim-engine`).
- `academy.sim_definitions` (`kind='branching_scenario'`), `academy.sim_attempts` (`safety_veto_triggered`), `academy.sim_telemetry_events`.
- S1's AC-203 critical-safety line-item keys (the ⚠ keys) so veto-relevant branches map to them.

## Tasks (ordered)
1. Author the **AC-103 "Trapped or Free?"** branching spec (a first-person walk through a store during a fire alarm; at each door tap "I can get out" / "I'm trapped" then see why; a chained exit and a no-release mag lock visibly trap; a compliant sensor-release door opens). Awareness tier → ≥90% gate (safety content). Validate against the F5 schema.
2. Author the **AC-203 egress-fail flagship** branching spec (mandatory to pass AC-203): the learner commissions a simulated mag-lock egress door making a sequence of real decisions — fail-state, motion-REX sufficiency, push-to-exit placement, release time, fire-alarm interface — then a simulated fire alarm fires and a crowd tries to exit. **Wrong choices trap occupants** (door stays locked / occupant the PIR misses is trapped / button too high/far/short); the correct build releases everyone. Map veto-relevant wrong branches to the S1 `ac203.*` critical-safety keys with `safety_flag`.
3. Implement the **post-mortem replay** (experience-design §1.4): after a safety-veto failure, replay the emergency from the occupant's POV, freeze at the trap, overlay the deciding choice + the governing code line (NFPA 101 §7.2.1.6.2), then drop back **to the decision**, not the start.
4. Ensure scoring/feedback runs through the **shared Verdict service** (instant, specific, diagnostic — names the consequence + the fix), EN+ES, colorblind-safe.
5. Telemetry: emit branch-choice xAPI statements (queued offline, `client_event_uuid`).
6. Wire the AC-203 hard-gate rule: the egress-fail sim **must be passed** for AC-203 progression (the gate is enforced server-side via mastery verdict; the sim feeds it).

## Done-criteria (testable)
- A **wrong egress choice shows the trapped-occupant consequence** and is scored; a safety-flagged wrong choice triggers the veto (`sim_attempts.safety_veto_triggered=true`) → fail.
- The AC-203 egress-fail sim is **mandatory**: AC-203 cannot be marked passed without a passing run (verified via the gating path).
- The post-mortem replay fires on safety-veto failure and returns the learner to the deciding node.
- Renders in both rich and 2D-fallback modes with identical Verdict/score; EN+ES; colorblind-safe.
- Branch telemetry queues offline and reconciles.

## Out of scope
- The WebGL Virtual Door "Do one" build for AC-203 (that is **M5**) — M3 is the branching judgment sim only.
- The field sign-off (M6) and badge (M7).
- AI elaboration of feedback (M10) — M3 uses the authored Verdict wording; M10 layers AI later.
- The branching **engine** itself (built in F5) — M3 authors specs against it.

## Invariants in play
- Inv. 1 (safety-veto via Verdict; the AC-203 ⚠ lines; never simplified — a wrong egress choice cannot be scored as a pass).
- Inv. 4 (offline telemetry; never fake a pass — verdict server-authoritative).
- Inv. 5 (consume F5's schema/engine; do not fork).
- Inv. 7 (colorblind-safe; EN+ES; keyboard-navigable).

## Tests required
- **Unit:** the AC-103 + AC-203 specs validate against the F5 schema; veto-branch → fail mapping; post-mortem trigger.
- **e2e (Playwright):** play AC-203 egress-fail, make the trapping choice → see consequence + veto + replay; make the compliant build → pass.
- **offline:** branch telemetry queues + reconciles.
- **a11y:** axe + keyboard path; no color-only pass/fail (the egress sim must use shape+text+color).

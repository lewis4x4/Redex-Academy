# F3 — Auth + SSO + Shared-Auth Identity + JWT Claims

- **Effort tier:** ultracode
- **Phase:** 0 (Foundation)
- **HUMAN-GATE:** identity model + JWT-claim → RLS interaction reviewed before merge (ledger §J).

## Objective
Wire Supabase Auth + OIDC/SAML SSO and the custom-JWT-claim mechanism that populates `org_id`, `role(s)`, `persona`, and `evaluator_authorized` (+ authorized `domains`) so RLS works. Lock the identity model to **greenfield / one shared Supabase project / shared `auth.users`** (ledger §A) — there is no Work OS federation path.

## Depends on
- **F2** (the `academy` schema, RLS keyed on `auth.jwt()->>'org_id'`, the generated types). RLS from F2 is inert until F3 populates the claims.

## Consumes (contracts)
- `academy.users` (`id = auth.users.id`), `academy.user_roles`, `academy.orgs`, `academy.evaluator_authorizations`.
- The RLS policies from F2 that read `auth.jwt()->>'org_id'`, `->>'role'`, `->>'evaluator_authorized'`.
- `.env` names: `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `SUPABASE_JWT_SECRET`.

## Tasks (ordered)
1. Configure Supabase Auth as the token issuer; enable **OIDC/SAML SSO** (Google Workspace / Microsoft Entra as the likely IdP) for Redex staff and CCS subcontractor orgs. Support invited managed accounts for partners without their own IdP.
2. Implement the **custom JWT claim injection** via the named mechanism: a Supabase **Auth Hook (`custom_access_token_hook`)** that, on token mint/refresh, enriches claims with `org_id`, `role(s)`, `persona`, `evaluator_authorized`, and authorized `domains` — read from `academy.users`/`user_roles`/`evaluator_authorizations`. (Do not invent a different mechanism; if the hook cannot carry an array claim cleanly, surface it.)
3. Ensure claims **refresh when roles change** (re-mint on role/authorization update; document the refresh path).
4. Implement the auth flow in `apps/web` (and `apps/admin`): login/logout, session handling, persona-adaptive UI selection from the `persona` claim, role-gated routes from `role` claims. Field-first low-literacy/dyslexia-friendly mode for the Marco persona on mobile.
5. **Lock the identity decision in code + docs (ledger §A):** one project, two schemas, `academy.users.id = auth.users.id`. Confirm the `REDEX_WORKOS_*` env path is absent (deleted in F1). Add a guard test/lint asserting no `work_os_user_id` reference exists anywhere in the codebase or schema.
6. Provision a small set of **dev identities** across two orgs (a Redex org + a CCS-partner org) with assorted roles for downstream isolation tests (used by M12).
7. Verify the F2 RLS now functions end-to-end: a logged-in user's `org_id` claim drives row visibility.

## Done-criteria (testable)
- A user logs in via OIDC; the issued JWT carries `org_id`, `role(s)`, `persona`, `evaluator_authorized` (+ `domains`).
- After login, F2's RLS returns the correct own-org rows and **zero** cross-org rows (the claim is live).
- Changing a user's role re-mints/refreshes the claim; the new permissions take effect.
- The Marco persona renders the field-first mobile UI; an exec/manager persona renders the dense mode.
- Guard test passes: **no `work_os_user_id`** anywhere; no `REDEX_WORKOS_*` env usage.
- `[HUMAN-VERIFY]` a human reviews the Auth Hook claim logic and the claim→RLS interaction before merge.

## Out of scope
- The `workos` schema/FK (F2a) and Work OS API federation (does not exist in this model).
- Sign-off, credential, or sim logic.
- The full CCS isolation adversarial test (that is **M12**) — F3 only provisions the identities and proves basic isolation.

## Invariants in play
- Inv. 3 (RLS tenant isolation — F3 makes it live via the `org_id` claim).
- Inv. 6 (one identity space; `academy.users.id = auth.users.id`; no Work OS user id).
- Secrets: OIDC secrets server-side only; never in the client bundle.

## Tests required
- **Unit:** Auth Hook claim-shaping logic (given a user with roles X/Y in org Z → expected claim set).
- **e2e (Playwright):** login flow; a same-org read succeeds and a cross-org read returns zero rows; role change updates access.
- **a11y:** login + persona-switched shells pass axe; keyboard-navigable.
- **Guard:** static check for absence of `work_os_user_id` / `REDEX_WORKOS_*`.

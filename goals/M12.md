# M12 — SSO + One CCS Org Isolation Test

- **Effort tier:** ultracode
- **Phase:** MVP
- **HUMAN-GATE (HARD):** the RLS/tenant-isolation negative-test matrix is reviewed before merge (ledger §J; a CCS leak is a contractual breach). This is the RLS adversarial test.

## Objective
Onboard one CCS subcontractor org via SSO, run a tech through training + a field sign-off, and **prove tenant isolation**: a CCS tech can do the same courses and sign-offs but **cannot see any Redex (or other partner) rows**. Effectively the adversarial RLS test for the whole slice.

## Depends on
- **F3** (SSO + the `org_id` claim + the provisioned Redex + CCS dev identities), **M6** (the sign-off path the CCS tech exercises). (Exercises the full slice M1–M7.)

## Consumes (contracts)
- The F3 SSO + JWT claims; F2/F2a RLS policies (the trust boundary under test).
- The shared published catalog (cross-tenant) vs personal data (own-org) policies.
- All slice tables (`enrollments`, `competency_state`, `signoffs`, `signoff_evidence`, `credentials`, `sim_attempts`, `workos.jobs`).

## Tasks (ordered)
1. **Onboard a CCS partner org** (`orgs.type='ccs_partner'`, nested under Redex via `parent_org_id`) with SSO (federated, or managed invited accounts). Provision a CCS tech + a CCS manager.
2. Run the CCS tech through the slice: enroll (M1), lessons/checks (M2), the sims (M3/M4/M5), a field sign-off (M6) against a CCS `workos.jobs` row, and a badge (M7) — proving the **same courses + same rubric, different `org_id`** model (curriculum §4b).
3. **Author the negative-test matrix (build-readiness §1 M12, §5):** the explicit set of queries that MUST return **zero rows** cross-org — for every personal/tenant table: a CCS actor reading Redex (and other-partner) `enrollments`/`unit_progress`/`competency_state`/`signoffs`/`signoff_evidence`/`credentials`/`sim_attempts`/`workos.jobs` → zero; and the reverse (Redex actor reading CCS personal data) → zero. Published catalog rows ARE visible cross-tenant (the allowed exception).
4. Confirm **state-changing writes** remain server-only for the CCS org too (no client write to `competency_state`/`credentials`/`signoffs.outcome`).
5. Confirm **evidence** is never returned inline to a cross-org actor (signed-URL re-auth fails cross-org).
6. Run the matrix as a **committed, locked adversarial test** (generalizes the F2/F2a RLS-negative tests to the full slice + the CCS org).

## Done-criteria (testable)
- A **CCS tech trains + is signed off** on the slice (full loop works for the partner org).
- **Isolation proven:** every query in the negative-test matrix returns **zero rows** cross-org (CCS↔Redex, CCS↔other-partner) for all personal/tenant tables; published catalog is the only cross-tenant-visible data.
- No client path lets a CCS user write state tables or read another org's evidence (even via signed URL).
- The adversarial matrix runs in CI as a locked test.
- `[HUMAN-VERIFY]` **HARD GATE:** a human reviews the negative-test matrix + the isolation result before merge (contractual breach risk).

## Out of scope
- New features — M12 exercises the existing slice (M1–M7) for a second org and proves isolation.
- Full CCS onboarding at scale (Phase 2).
- The exec dashboard (Phase 2).

## Invariants in play
- Inv. 3 (RLS deny-by-default + tenant isolation — this goal is its adversarial proof; never weakened).
- Inv. 2 (state writes server-only — proven for the partner org too).
- Inv. 6 (one identity space; org separation is by `org_id` claim, not separate user spaces).
- Security: cross-org evidence access via signed URL must fail.

## Tests required
- **RLS adversarial matrix (locked):** the full zero-rows-cross-org query set across all personal tables, both directions, plus the allowed published-catalog exception.
- **e2e (Playwright):** CCS tech full slice loop (enroll → learn → sim → sign-off → badge); a CCS user attempting to view a Redex record gets nothing.
- **Security:** cross-org signed-URL evidence fetch denied; no client state write for CCS.
- **Human-verification stub:** committed checklist for the isolation review.

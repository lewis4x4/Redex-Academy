# M11 — Manager Sign-Off Pipeline Dashboard (Realtime)

- **Effort tier:** standard
- **Phase:** MVP

## Objective
Build the manager's live sign-off pipeline board on Supabase Realtime: candidates by stage (sim-passed → awaiting Evaluator → signed/failed), the Evaluator queue/workload, first-attempt sign-off pass rate, and recert/overdue gates — reading aggregated views (no raw PII beyond the manager's org scope), with evidence drill-down via signed URLs.

## Depends on
- **F3** (auth + manager role + org scope), **M6** (the sign-off data + stages the board reflects).

## Consumes (contracts)
- `academy.signoffs` (`status`, `outcome`, stages), `academy.competency_state`, `academy.enrollments`, `academy.evaluator_authorizations`, `academy.signoff_evidence` (signed-URL access).
- Supabase Realtime; the F3 `org_id`/`role` claims.

## Tasks (ordered)
1. Define **which Postgres changes publish over Realtime** (build-readiness §1 M11 gap): the sign-off pipeline stage changes (`sim_passed → awaiting_evaluator → signed/failed`) and Evaluator-queue updates — scoped to the manager's org. Configure Realtime publications/policies accordingly.
2. Build the **live board** in `apps/web` (manager view): candidates by stage, the Evaluator queue + workload, **first-attempt sign-off pass rate** (curriculum §4e — flags a sim-to-reality gap or a too-soft rubric), recert compliance by team/site, overdue gates. Colorblind-safe stage rendering.
3. Implement **aggregated reads / no-raw-PII** (wave3 §9/§10): managers read their org's data; exec/aggregate views expose summaries, not raw cross-tenant PII. Evidence drill-down is via **short-lived signed URLs** minted after re-auth (never inline SELECT).
4. Ensure RLS scopes everything to the manager's org; cross-org rows never appear.

## Done-criteria (testable)
- The board shows the **live pipeline**: a candidate moving sim-passed → awaiting Evaluator → signed updates in real time (Realtime).
- First-attempt pass rate, Evaluator workload, and recert/overdue gates render for the manager's org.
- Evidence drill-down opens via a signed URL (re-authorized), not an inline SELECT.
- Cross-org data never appears (RLS); the board is read-only (no state writes from the dashboard).

## Out of scope
- The sign-off creation/finalize logic (M6) — M11 is the read-side board.
- The exec ROI dashboard + Work OS KPI joins (Phase 2).
- AI analytics / LRS behavioral dashboards (Phase 2).
- Bulk telemetry over Realtime (that's the LRS — Realtime is for the pipeline only).

## Invariants in play
- Inv. 2 (read-side only; the dashboard never writes state).
- Inv. 3 (RLS — manager sees own org only; aggregated/no-raw-PII for exec reads).
- Inv. 7 (colorblind-safe stage rendering; a11y).
- Security: evidence via signed URLs, re-authorized (wave3 §10).

## Tests required
- **e2e (Playwright):** a sign-off stage change propagates to the board in real time; first-attempt pass rate computes; evidence opens via signed URL.
- **RLS-negative:** a manager sees zero rows from another org.
- **a11y:** the board passes axe; no color-only stage encoding.

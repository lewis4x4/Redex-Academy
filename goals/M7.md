# M7 — OB 3.0 Issuance for the Slice (Skill → Tier Stackable)

- **Effort tier:** ultracode
- **Phase:** MVP
- **HUMAN-GATE (HARD):** credential signing / key custody / server-only issuance reviewed; "badge verifies at a public URL" `[HUMAN-VERIFY]` (ledger §J).

## Objective
Issue the slice's Open Badges 3.0 credentials from real sign-offs: when a candidate's component skill badges are all `field_proven`, issue the skill badges with evidence URLs and **auto-issue the stackable tier credential "Certified Technician — Access Control"**, all signed by the F6 issuer.

## Depends on
- **F6** (the issuer: proof suite `eddsa-rdfc-2022`/Ed25519, `did:web` issuer profile, status list, the `issue-badge` Edge Function or Node microservice per the F6 decision, the credential builder), **M6** (the `finalize-signoff` path that flips `field_proven` and triggers issuance), **S1** (the slice `badge_classes` + `requires` stackability chain).

## Consumes (contracts)
- `academy.badge_classes` (`kind`, `requires` — the S1 stackability chain), `academy.credentials` (`open_badge_json`, `proof`, `hosted_assertion_url`, `evidence_urls`, `status`), `academy.competency_state` (`field_proven`), `academy.signoff_evidence` (for `evidence_urls`).
- F6's credential builder + `issue-badge` signer + status list.

## Tasks (ordered)
1. Implement the **stackability rollup** (build-readiness §1 M7 gap): a server-side resolver that, on a `field_proven` event (from M6), checks `badge_classes.requires` and:
   - issues the corresponding **skill badge** (e.g., *Mag Lock + REX + Egress Wiring* for AC-203) with **evidence URLs** pointing at the real `signoff_evidence` / Work OS job records; and
   - when ALL component skill badges for a tier credential are held/`field_proven`, **auto-issues** the **tier credential** *Certified Technician — Access Control* (ledger §D auto-issue rule).
2. Call F6's **`issue-badge`** to construct + **sign server-side** the OB 3.0 / VC (recipient `achievement`, `issuer` DID, `evidence`, expiry, `credentialStatus` from the status list, `proof`), write `credentials`, publish the hosted verifiable assertion. **Signing never on the client.**
3. Surface the **Digital Backpack** in `apps/web`: earned/expiring badges, the stack (skill → tier), each with its hosted verifiable URL.
4. Wire **expiry/recert** metadata from `badge_classes.recert_months`/`is_compliance` (the egress 12-mo rule) into the issued credential (the recert engine itself is Phase 2; M7 sets the data).
5. Ensure **revocation** path works (flip status → status list updates, via F6).

## Done-criteria (testable)
- On a passing AC-203 sign-off (`field_proven`), the **skill badge issues with evidence URLs** (real `signoff_evidence`/job refs) and verifies.
- When all slice skill badges are `field_proven`, the **tier credential auto-issues** (stackable) and verifies.
- Issued credentials are **signed server-side** (F6 proof suite); the private key never appears client-side.
- The Digital Backpack shows the stack with working hosted verifiable URLs.
- Expiry/recert metadata is set on the credential (egress 12-mo).
- `[HUMAN-VERIFY]` **HARD GATE:** a human confirms a slice badge **verifies at a public URL**, reviews the stackability rollup + key custody + server-only signing before merge.

## Out of scope
- Building the issuer itself (F6) — M7 consumes it.
- The sign-off path (M6) — M7 reacts to its `field_proven`/issuance trigger.
- The full recert engine + N8N targeting (Phase 2) — M7 sets credential expiry metadata only.
- Manager dashboard (M11).

## Invariants in play
- Inv. 2 (issuance/revocation server-only; never client; signing in F6's server context).
- Inv. 5 (consume F6's builder + S1's `requires` chain; do not invent the credential shape or the stack).
- Inv. 1 (a badge can only issue off a `field_proven` sign-off that passed the safety veto — never off a faked/vetoed pass).

## Tests required
- **Unit:** the stackability rollup (skill → tier auto-issue when `requires` satisfied); evidence-URL binding; expiry metadata.
- **e2e:** pass AC-203 sign-off → skill badge issues + verifies; complete the stack → tier credential auto-issues + verifies; revoke → status list reflects it.
- **Security:** issuance/signing unreachable client-side; key not in bundle.
- **Human-verification stub:** committed checklist for the public-URL verification of a slice badge.

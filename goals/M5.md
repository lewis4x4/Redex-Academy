# M5 — WebGL Install Sim (AC-201/203 Mag-Lock / REX / Egress Wiring)

- **Effort tier:** ultracode
- **Phase:** MVP
- **Rationale for tier:** spatial wiring correctness + the safety-fail verdict (normally-open mag-lock) is a safety-relevant decision; perf-budgeted 3D is hard.

## Objective
Build engine #3 (WebGL 3D install) on the F5 framework and ship the AC-201/AC-203 Virtual Door "Do one" rehearsal: wire a mag-lock + REX + fire-alarm interface in 3D, prove all three release modes; **a normally-open mag-lock wiring triggers a safety fail** via the Verdict service.

## Depends on
- **F5** (shared framework: Verdict/safety-veto, xAPI emitter, offline cache, i18n, colorblind-safe, 2D fallback primitives), **S1** (AC-201/AC-203 units/competencies + AC-203 line-items), **M1** (gating).

## Consumes (contracts)
- F5 `packages/sim-engine` API + Verdict service + 2D fallback; F5's offline cache contract.
- `academy.sim_definitions` (`kind='webgl_install'`), `academy.sim_attempts` (`safety_veto_triggered`), `academy.sim_telemetry_events`.
- S1's `ac203.*` critical-safety line-item keys (so wiring fail-states map to the veto).

## Tasks (ordered)
1. Build **engine #3 (WebGL 3D install)** on the F5 framework using **React-Three-Fiber / Three.js** (+ drei for camera rigs, outlines, HTML-in-3D labels). **Rapier physics is deferred from MVP** (ledger §E/§K) — do not add a physics engine.
2. Author the **R3F scene + interaction manifest JSON Schema + Zod** (in `packages/sim-schemas`): objects (glTF refs), **snap points**, **correct/incorrect placements**, tool interactions, **wiring connections + wiring rules**, and **fail-states** — each rule tagged to a §5.4 dimension with `safety_flag` where life-safety-relevant. (This extends the F5 schema family; reuse the Verdict contract.)
3. Author the **AC-201/AC-203 Virtual Door** scene: terminate conductors to terminals, set relay logic / lock fail-state, wire REX (PIR + push-to-exit) and the fire-alarm release interface, power up, verify all three release modes (power loss, push-to-exit ≥30s, fire alarm). Map fail-states to the S1 `ac203.*` ⚠ keys.
4. **The named safety-fail (build-readiness §1 M5 "good criterion"):** wiring a mag-lock **normally-open** (so it would NOT release on power loss / NOT fail-safe) **triggers a safety fail** through the Verdict service (veto → `sim_attempts.safety_veto_triggered=true`). Likewise motion-REX-only (no push-to-exit), missing fire-interface, push-to-exit at wrong height/distance/<30s → fail.
5. **glTF asset pipeline (mobile perf-budgeted):** Draco-compressed models from R2, LOD, lazy load, offline-cacheable via F4. Set an explicit **FPS + asset-size budget** and assert it (it must run on a tech's phone).
6. Wire the **2D picture-book fallback** for low-power phones/field: same sim state, same Verdict, same scoring, rendered as a high-contrast 2D schematic with the same drag targets (first-class, not degraded).
7. Telemetry: emit interaction/wiring xAPI (queued offline). EN+ES; keyboard-navigable (ARIA roles on terminal/conductor/node); colorblind-safe.

## Done-criteria (testable)
- **Normally-open mag-lock wiring triggers a safety fail** (veto via Verdict; `safety_veto_triggered=true`). Other fail-states (motion-REX-only, missing fire-interface, bad push-to-exit) also fail.
- A correct mag-lock + REX + push-to-exit + fire-interface build proving all three release modes **passes** (≥90% safety bar).
- The sim runs in 3D **and** in the 2D fallback with identical Verdict/score.
- **Perf budget met:** FPS + asset-size budget asserted on a mobile-class profile; assets Draco-compressed, lazy-loaded, offline-cacheable.
- Telemetry queues offline and reconciles; EN+ES; keyboard-navigable; colorblind-safe.
- `[HUMAN-VERIFY]` (ultracode + safety-relevant): a human reviews the wiring-rule → veto mapping and the perf-on-real-device behavior before release.

# M6 — §5.4 Sign-Off + Line-Items + Safety-Veto Trigger Wiring + Work OS Job Evidence

- **Effort tier:** ultracode
- **Phase:** MVP
- **HUMAN-GATE (HARD):** the three-layer safety-veto enforcement + the rubric line-item data are reviewed before merge (ledger §J; build-readiness §6). The single most liability-critical goal.

## Objective
Build the Evaluator field sign-off against a **Work OS job id**, the §5.4 four-dimension / 0–3 / safety-veto rubric using the **per-course line-items** (incl. AC-203's ⚠ lines), the `finalize-signoff` Edge Function, evidence capture wired to Work OS job photos, and `competency_state` promotion to `field_proven` — with the safety veto enforced in **DB trigger + Edge Function + UI** (defense in depth).

## Depends on
- **F2a** (the cross-schema FK `academy.signoffs.work_os_job_id → workos.jobs(id)`; demo jobs), **F3** (auth + the `evaluator_authorized`/`domains` claim), **F4** (offline draft path + `/sync` rejection of illegal server-only writes), **S1** (the AC-201/202/203 line-item catalog + `is_critical_safety` flags + competencies).

## Consumes (contracts)
- `academy.signoffs` (`status`, `outcome`, `work_os_job_id`, immutability), `academy.signoff_line_items` (`dimension`, `line_item_key`, `score 0..3`, `is_critical_safety`), `academy.signoff_evidence` (`kind`, `r2_key`, `work_os_ref`), `academy.competency_state` (server-only promotion).
- The **F2 safety-veto trigger + immutability trigger** (the DB layer — already built); M6 wires the Edge Fn + UI layers to match.
- `workos.jobs` (F2a) for the job link + evidence refs.
- S1's `ac203.*` critical-safety keys.

## Tasks (ordered)
1. Build the **sign-off UI** for Evaluators: select a candidate + the competency/skill-badge target + a **Work OS job id** (from `workos.jobs`, own-org only); score each §5.4 line item 0–3 across the four dimensions, pulling the **per-course line-item set** (AC-203's ⚠ lines from S1, etc.). Evaluator must hold `evaluator_authorized` for the domain (`domains` claim). Colorblind-safe; mobile-first (signed in the field).
2. Build the **`finalize-signoff` Edge Function** (service-role, server-authoritative): validate the four-dimension rubric, **enforce the pass rule** — `outcome='pass'` ONLY IF every dimension rollup ≥2 AND every `is_critical_safety` line ≥2; a single `0` on any safety line ⇒ `fail`, non-overridable (ledger §B). On pass, record evidence links, flip `competency_state` to `field_proven`, and **trigger badge issuance** (hand to M7's `issue-badge`). This is the only path that writes the sign-off outcome + promotes competency.
3. **Defense in depth (build-readiness §6):** the veto is enforced at **all three layers** — DB trigger (F2), the `finalize-signoff` Edge Fn (this goal), and the UI (this goal). The UI veto is UX; the DB is the trust boundary; test all three.
4. **Evidence capture wired to Work OS:** evidence is the job's own photos/signatures/closeout (referenced by `work_os_ref`) plus a Redex-owned immutable copy in R2 (`r2_key`); no double data entry. Sensitive evidence accessed via signed URLs (wave3 §10), never inline SELECT.
5. **Immutability:** once `signed`, the sign-off + its line items are locked (DB trigger from F2); corrections require a **new voiding sign-off** with audit trail. The `/sync` path (F4) and the Edge Fn both reject late edits.
6. **Offline:** sign-off **drafts** + evidence Blobs queue offline (F4); finalize is **server-only** (never finalized offline; "will complete on reconnect"). The client cannot fake a pass.
7. Write to the `audit_log` for every finalize/void (append-only).

## Done-criteria (testable)
- An Evaluator (authorized for AC) **signs off a candidate against a Work OS job id**; evidence (job photos / Work OS refs + R2 copy) is attached.
- **Safety `0` ⇒ auto-fail** at all three layers: a single `0` on any AC-203 ⚠ line forces `outcome='fail'`, non-overridable — proven in the DB trigger, the Edge Fn, and blocked in the UI.
- **Pass rule:** every dimension ≥2 AND every critical-safety line ≥2 → `pass` → `competency_state='field_proven'` → badge issuance triggered.
- **Row immutable after sign:** a late UPDATE/DELETE (via API, `/sync`, or UI) to a `signed` sign-off is rejected; a correction is a new voiding sign-off.
- An Evaluator NOT authorized for the domain cannot finalize.
- Cross-org Evaluators/managers see zero of another org's sign-offs (RLS).
- The finalize path is **server-only**; an offline client cannot promote competency or set outcome.
- `[HUMAN-VERIFY]` **HARD GATE:** a human reviews the three-layer veto + the rubric line-item data + the Work OS evidence binding before merge.

# F4 — Offline PWA Shell + IndexedDB + Idempotent `/sync`

- **Effort tier:** ultracode
- **Phase:** 0 (Foundation)
- **HUMAN-GATE:** real-hardware airplane-mode verification + "never fakes a pass" + immutable-after-sign rejection (ledger §J).

## Objective
Build the offline-first PWA spine: Workbox service worker precaching the app shell + on-demand "field pack" download, Dexie/IndexedDB durable local store for in-progress attempts/telemetry/sign-off drafts/queued xAPI, and the **idempotent `/sync` Edge Function** that reconciles on reconnect without losing work or faking a pass. This is the program's #1 risk bet (wave3 §12.6).

## Depends on
- **F2** (event tables with `UNIQUE(client_event_uuid)`; `competency_state`/`signoffs` server-authoritative; generated types).

## Consumes (contracts)
- `academy.sim_telemetry_events`, `academy.sim_attempts`, `academy.unit_progress`, `academy.assessment_responses`, `academy.signoffs` (draft path) — all with `client_event_uuid`.
- Inv. 4 (offline never fakes a pass) and ledger §G sync correctness rules.

## Tasks (ordered)
1. Implement the **service worker** (Workbox) in `apps/web`: precache app shell; runtime strategies (cache-first hashed assets, network-first API, stale-while-revalidate catalog). Register/update lifecycle with an explicit update prompt.
2. Implement **field-pack download**: on demand, cache a course's sim HTML/JS, JSON specs, images, captions, checklists, and the sign-off rubric. Video is **not** force-cached — offer explicit per-video "download for offline" to R2/Stream-origin MP4.
3. Implement the **Dexie/IndexedDB** schema for: downloaded course packs, in-progress sim attempts + telemetry, queued sign-off **drafts** + evidence photo Blobs, queued xAPI statements. Every locally-generated fact carries a **client-generated UUID + device timestamp**.
4. Implement the **`/sync` Edge Function** (Deno) — **idempotent keyed on `client_event_uuid`**:
   - Append-only events (telemetry, progress ticks, attempts, responses) → upsert-by-UUID; replaying the same payload is a no-op.
   - Mutable drafts/prefs → **last-writer-wins** tie-broken by **server receipt time** (+ device-clock-skew tolerance); surface a conflict to the user only if both sides changed.
   - **Server-only computations are NEVER accepted from the client (ledger §G):** competency promotion, mastery verdict, sign-off finalize/outcome, badge issuance, recert scheduling. `/sync` rejects any payload attempting to set these. A finalized/`signed` sign-off is **immutable** — late edits rejected.
5. Implement the client **sync queue + flush** on reconnect (online event + periodic retry with backoff); make sync state **unmissable** in the UI (an un-synced job "looks done but doesn't exist to the business" — INT-102). Show clear "will complete on reconnect" states for anything needing server authority.
6. Build a **Playwright offline harness** (`context.setOffline(true)`) proxy DoD: download a pack, run an action offline, queue it, go online, assert idempotent reconciliation and that **no pass was fabricated offline**.
7. Produce a **human-verification artifact + checklist** for the real-hardware test (the proxy cannot replace it): mark the goal "pending human verification," not "done."

## Done-criteria (testable)
- **Automatable proxy (CI):** with Playwright offline, a downloaded pack runs offline; queued events flush on reconnect; replaying a flush is idempotent (no duplicate rows — proven via `client_event_uuid`).
- **Never-fake-a-pass test:** an offline attempt cannot promote `competency_state` or set a sign-off `outcome`; the server computes verdicts only; `/sync` rejects client-set state fields.
- **Immutability test:** a late edit to a `signed` sign-off is rejected by `/sync` (and by the DB trigger from F2).
- **LWW test:** concurrent draft edits resolve by server receipt; a genuine two-sided conflict is surfaced, not silently dropped.
- `[HUMAN-VERIFY]` **real hardware, airplane mode:** download a field pack on a phone, run a sim offline, reconnect, reconcile telemetry — no lost work, no faked pass, immutable-after-sign holds. A qualified reviewer signs the checklist before release.

## Out of scope
- The actual sim engines (F5/F5b) — F4 syncs whatever event shapes they emit; use a stub event for the harness.
- xAPI→LRS forwarding (that is **M8**) — F4 queues xAPI locally; M8 wires the bridge.
- Sign-off finalize logic / badge issuance (M6/M7) — F4 only handles the **draft** and the rejection of illegal server-only writes.

## Invariants in play
- Inv. 4 (offline never fakes a pass; append-only + `client_event_uuid`; idempotent `/sync`; immutable signed sign-offs; LWW only for drafts/prefs).
- Inv. 2 (server-only state computations).
- Inv. 5 (contract-first — emit events against F2's tables, don't invent new ones).

## Tests required
- **Unit:** `/sync` idempotency (UUID replay), LWW tie-break, rejection of server-only fields, immutable-signed rejection.
- **e2e/offline (Playwright):** the full download→offline→reconnect→reconcile path; sync-state UI visibility.
- **Human-verification stub:** committed checklist artifact for the real-device airplane-mode run.

# M9 — Authoring Admin v1 (Content-as-Data)

- **Effort tier:** ultracode
- **Phase:** MVP

## Objective
Build the in-repo authoring admin (`apps/admin`) so Curriculum can load/edit a lesson and a sim spec **with no deploy** — forms over the F2 schema + the F5/F5b sim JSON Schemas, with a preview/sandbox harness and the publish workflow (incl. the localization + safety-review gates).

## Depends on
- **F2** (the content tables + generated types), **F5** (branching + device-config schemas + the preview harness), **F5b** (2D-interaction + calculator schemas).

## Consumes (contracts)
- The generated types (`packages/db-types`), the published sim JSON Schemas + Zod (`packages/sim-schemas`), the F5 preview/sandbox harness (`packages/sim-engine`), `packages/i18n` (the locked safety glossary).
- `academy.courses`/`course_versions`/`units`/`assessment_items`/`sim_definitions`/`fixture_sets`.

## Tasks (ordered)
1. Build **content-as-data forms** in `apps/admin` over the schemas: edit courses/units/assessment_items; author **sim specs** via schema-driven forms (branching graph, device-config rules, 2D-interaction mappings, calculator inputs/thresholds) — validated against the published JSON Schema + Zod before save. MDX editing for lesson bodies with the M2 component contract.
2. Integrate the **preview/sandbox harness** (F5): render the exact learner experience (including the 2D fallback + offline) before publish.
3. Implement the **versioning workflow** (wave3 §8.2): editing a published course creates a new `course_version` (draft); published versions are immutable; on publish the author sets the SemVer bump (PATCH/MINOR/MAJOR) and updates the `platform_manifest`.
4. Implement the **review/publish gates** (wave3 §8.1, build-readiness §6 content gate): `author` drafts → `curriculum_admin` publishes; **safety/egress content requires SME + a safety-reviewer sign-off** before publish; a version is not "publishable for field" until EN+ES strings + the locked safety-glossary terms are complete/reviewed. **Fixtures require `sanitized=true`** (the publish gate) — surface unsanitized fixtures as blocked.
5. Enforce **role-gating** (RLS + UI): only `author`/`curriculum_admin` reach authoring; writes respect RLS.
6. **No Lovable runtime** (build-readiness §7): the admin is built in-repo directly.

## Done-criteria (testable)
- A `curriculum_admin`/`author` **loads a lesson + a sim spec with no deploy**; the spec validates against the published JSON Schema before save; an invalid spec is rejected with clear errors.
- The preview harness renders the authored lesson/sim (rich + 2D fallback) before publish.
- Editing a published course creates a new draft `course_version`; publishing requires the SemVer bump + manifest update.
- **Gates enforced:** safety/egress content cannot publish without SME + safety-reviewer sign-off; a version cannot publish for field without complete EN+ES + glossary; an unsanitized fixture is blocked from publish.
- Non-author roles cannot reach authoring (RLS + UI).

## Out of scope
- The reusable engines/schemas (F5/F5b) — M9 is forms **over** them.
- Fixture **capture/sanitization** itself (SME human process) — M9 enforces the sanitized gate.
- The firmware-change → targeted-recert pipeline + N8N (Phase 2).
- Authoring content for the other 5 domains (Phase 2).

## Invariants in play
- Inv. 5 (contract-first — authoring is forms over the existing schemas; the admin never defines new sim shapes).
- Inv. 1 (safety/egress content publish gate; locked safety glossary non-overridable).
- Inv. 3 (RLS — authoring role-gated; published content org-agnostic).
- Inv. (sanitized-fixture publish gate from F1 CI).

## Tests required
- **Unit:** schema-driven form validation (valid/invalid specs); the versioning bump logic.
- **e2e (Playwright):** author a sim spec → preview → attempt publish; the safety-review gate blocks publish until signed; the sanitized-fixture gate blocks an unsanitized fixture.
- **RLS/role:** a non-author cannot access `apps/admin` authoring routes.
- **a11y:** admin forms pass axe.

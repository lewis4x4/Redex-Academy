# F2 — Academy Schema Apply/Install + RLS + Generated Types

- **Effort tier:** ultracode
- **Phase:** 0 (Foundation)
- **HUMAN-GATE:** RLS policies reviewed before merge (ledger §J).

## Objective
Apply/install the `academy` Postgres schema (tables, Postgres enums, indexes, the safety-veto trigger, the immutability trigger, the DAG-check function), turn on deny-by-default RLS with tenant isolation, and wire `supabase gen types typescript` so the committed `packages/db-types/database.types.ts` becomes the single contract every later goal imports.

> **Note:** the authoritative DDL/migration SQL for `academy` is authored **separately** (the "F2 schema" artifact). This goal **applies/installs** that SQL via Supabase migrations, adds the policies/triggers/functions specified below if not already present in that artifact, runs typegen, and proves the invariants with committed tests. If the schema artifact and this spec disagree on a column/enum/policy, **STOP and surface it** — do not invent shapes.

## Depends on
- **F1** (monorepo, `supabase/migrations/`, `packages/db-types`, CI gates, `gen:types` task).

## Consumes (contracts)
- The separately-authored `academy` schema DDL (the migration SQL).
- `CLAUDE.md` invariants + the migration→typegen rule.
- Supabase CLI + `SUPABASE_DB_URL`/`SUPABASE_PROJECT_REF` (from `.env`, names only in repo).

## Tasks (ordered)
1. Land the `academy` schema as ordered Supabase migrations: `orgs`, `users` (`id = auth.users.id`, **NO `work_os_user_id` column** per ledger §A), `roles`/`user_roles`, `evaluator_authorizations`, `competencies` (+ `is_safety_critical`), `courses`/`course_versions`/`units`/`unit_competencies`, `course_prerequisites` (`kind {hard_gate|soft}`), `course_platform_dependencies`, `enrollments`/`unit_progress`/`competency_state`, `sim_definitions`/`fixture_sets`/`sim_attempts`/`sim_telemetry_events`, `signoffs`/`signoff_line_items`/`signoff_evidence`, `recert_schedules`, `badge_classes`/`credentials`, `assessment_items` (+ **`is_safety_item bool`**) /`assessment_responses`, `audit_log`.
2. **Enforce the ledger corrections in the schema:**
   - **Ledger §B:** add `academy.signoff_line_items (id, signoff_id FK, dimension enum {safety_compliance|technical_execution|verification_documentation|independence_judgment}, line_item_key text, score int CHECK 0..3, is_critical_safety bool, note)`. (Replaces/augments the prose `signoff_rubric_scores`.)
   - **Ledger §C:** mastery at the item level — `assessment_items.is_safety_item bool`. Keep `competencies.is_safety_critical` for badge/recert logic only.
   - **Ledger §G:** `UNIQUE(client_event_uuid)` on every append-only event table (`sim_telemetry_events`, `assessment_responses`, and any other event/log table).
3. Define Postgres **enums** as real enum types (not free text) for: `org.type`, `user.persona`, `user.status`, `role.key`, `course.tier`, `course.status`, `course_version.status`, `unit.kind`, `prereq.kind`, `enrollment.status`, `enrollment.enrolled_via`, `unit_progress.status`, `competency_state.status`, `competency_state.source`, `sim_definition.kind`, `sim_attempt.outcome`, `signoff.status`, `signoff.outcome`, `signoff_line_item.dimension`, `signoff_evidence.kind`, `recert_schedule.reason`/`.status`, `badge_class.kind`, `credential.status`, `assessment_item.kind`. Add the indexes needed for gating queries (FKs, `org_id`, `(user_id, competency_id)`, `client_event_uuid`).
4. **Safety-veto enforcement (ledger §B — defense in depth, this goal owns the DB layer):**
   - A **TRIGGER** (not a CHECK — it is cross-row) that sets/forbids `signoffs.outcome='pass'` ONLY IF every dimension rollup ≥ 2 AND every `is_critical_safety` line item ≥ 2; a single `0` on any safety line ⇒ `fail`, non-overridable.
   - An **immutability TRIGGER**: once `signoffs.status='signed'`, block UPDATE/DELETE on the signoff row and its `signoff_line_items`; corrections require a new voiding sign-off.
5. **RLS (ledger §A, wave3 §3.8/§7) — deny-by-default on every table:**
   - Tenant isolation: personal/tenant tables key on `org_id = (auth.jwt() ->> 'org_id')::uuid`.
   - Published catalog (`courses`/`course_versions`/`units`/`competencies`/`sim_definitions` published rows) readable cross-tenant via an explicit "published content is org-agnostic" SELECT policy; personal data (progress, sign-offs, credentials, evidence) strictly own-org.
   - **State-changing writes** to `competency_state`, `credentials`, `signoffs` (finalize), `recert_schedules` are granted to **no end-user role** — only the service role (Edge Functions) writes them. Client roles get SELECT (own scope) only.
6. **DAG-check:** implement the Postgres function/view that detects cycles in `course_prerequisites`; wire `infra/dag-check.ts` to call it and **fail CI** on any cycle (the curriculum had a broken `ADC-201` edge — make it un-shippable).
7. **PostgREST exposure (ledger §A):** expose the `academy` schema; set `search_path`; explicit `GRANT`s per role (`anon`, `authenticated`, `service_role`). Leave `workos` for F2a.
8. Run `supabase gen types typescript` → write to `packages/db-types/database.types.ts`; **commit it**. Verify `typegen-drift` CI passes.

## Done-criteria (testable)
- All migrations apply cleanly on a fresh Supabase instance; `supabase db reset` reproduces the schema.
- Generated types committed; `typegen-drift` CI job green.
- **RLS proof (pgTAP or SQL tests, committed):** a cross-org `authenticated` actor gets **zero rows** on every personal table; published catalog rows are readable cross-tenant; no client role can INSERT/UPDATE `competency_state`/`credentials`/`signoffs.outcome`.
- **Safety-veto proof (committed pgTAP/SQL, ledger §B mandatory):** all-2s sign-off → `pass`; one safety line `0` → `fail` (non-overridable); a late UPDATE/DELETE to a `signed` row is **rejected**.
- **DAG proof:** inserting a prerequisite cycle fails the DAG check; `dag-check` CI job fails on a seeded cycle and passes on the acyclic graph.
- `[HUMAN-VERIFY]` a human reviews every RLS policy + the negative-test matrix before merge.
